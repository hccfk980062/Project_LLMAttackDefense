一、本期摘要
================================================================================
本期主要完成三件事：

1. 找出並修正 L2 偵測器「幾乎把所有文件都判為注入」的根本原因（模型過期），
   重新訓練後，乾淨文件誤判率由 98.5% 降至 4.5%。
2. 修正兩個會使實驗結果失真的評估問題（FPR 抽樣錯誤、L5 規則內含測試答案），

3. 用修正後的設定重跑全部實驗，並整理文件與程式碼說明。

二、系統架構（回顧）
================================================================================
系統是一個 RAG 問答系統（FAISS 向量檢索 + gpt-4o-mini 生成），外加五層防禦：

  L1 輸入清理      正規化、長度限制、正則黑名單；也掃描檢索回來的文件
  L2 注入偵測器    微調 mBERT 二元分類器；掃描使用者查詢與檢索回來的文件
                   （命中的文件只丟棄該文件，不擋整個查詢）
  L3 提示詞分區    以 [SYSTEM]/[CONTEXT]/[USER] 標籤區隔信任等級
  L4 受控生成      temperature 0、輸出長度限制、可選 JSON 固定格式輸出
  L5 輸出驗證      通用正則、格式合規檢查、獨立模型 (gpt-4o) 稽核

L2 的定位是「檢查文件中是否夾帶間接注入指令」：使用者上傳文件時先掃描、
被標記的段落不寫入知識庫；查詢時再對檢索到的文件掃描一次，作為第二道防線。

三、本期發現的問題與處理方式
================================================================================
(1) L2 偵測器模型過期
    現象：L2 把 98% 以上的乾淨知識庫文件判為注入，導致防禦後雖然攻擊成功率 0%，
          但模型其實拿不到任何參考資料（可用性為零）。
    原因：使用中的模型是在「加入文件層級訓練資料」之前訓練的，只看過使用者查詢，
          沒看過正常文件長什麼樣子。調整判定門檻也無效（各門檻下誤判率與偵測率同起同落）。
    處理：用目前的訓練資料重新訓練。

(2) 訓練時間過長
    現象：L2 訓練一次約需 2 小時。
    原因：電腦有 NVIDIA RTX 3060 顯卡，但安裝的 PyTorch 是 CPU 版本。
    處理：改裝 GPU 版 PyTorch，訓練時間縮短為約 4 分鐘，L2 掃描延遲約 90 ms。

(3) 誤報率 (FPR) 的量測方式有誤
    現象：先前實驗得到 FPR 22.5%~28%。
    原因：用來測試的「良性問題」其中一部分其實是知識庫文件片段（例如「---」），
          而且全部都是 L2 的訓練資料，等於用考古題測驗。
    處理：另外撰寫 93 筆從未進入訓練資料的良性問題（知識庫問題、一般問題、
          含敏感字的邊界案例、多語言），並加入自動測試確保不會混入訓練資料。

(4) L5 規則內含測試答案
    現象：先前「只開 L5」時攻擊成功率為 0%。
    原因：L5 的正則規則直接寫入了測試攻擊要求模型輸出的標記字串，
          防禦端等於事先知道答案；實際攻擊者的字串是無法預知的。
    處理：將這些字串移出預設規則，只保留通用規則與 gpt-4o 稽核，並加入測試防止再次發生。
          修正後「只開 L5」的攻擊成功率為 12%。

(5) 實驗樣本數過少
    現象：間接注入實驗每組只有 8 次試驗，例如 6/8 (75%) 的 95% 信賴區間為 41%~93%，
          無法比較不同防禦配置的差異。
    處理：觸發問題由 8 個增加為 44 個（涵蓋全部 13 份知識庫文件），並使用 3 種不同的
          知識庫污染方式，每組共 132 次試驗；所有比率改為附上 Wilson 95% 信賴區間。
          另新增兩個指標：「乾淨文件被誤丟比例」與「仍有參考資料可回答的比例」，
          避免把文件全部丟棄的情況被誤認為防禦有效。

四、實驗結果（2026-10-25 重跑）
================================================================================
(1) L2 偵測器（離線評估，不需呼叫 API）
                                     舊模型          新模型
    乾淨文件誤判率                   98.5%           4.5%
    被污染文件偵測率                 100%（全判）     88% ~ 99%
    保留文件 (訓練時未見) F1         —               0.936
    手寫改寫攻擊句 F1                0.83            0.629
    註：加入文件資料後，對「換句話說」的攻擊問句偵測率下降（recall 0.71 → 0.46），
        是目前已知的取捨，詳見第六節。

(2) 實驗一：無防禦時的間接注入（132 次）
    乾淨知識庫：攻擊成功率 0%（0/44）
    被污染知識庫：攻擊成功率 72.0%（95/132，95% CI 64%~79%）
    → 使用者只是問正常問題，模型就會執行文件中的惡意指令。

(3) 實驗二：完整五層防禦（132 次）
    攻擊成功率：70.5% → 2.3%（3/132，95% CI 0.8%~6.5%）
    被污染文件被丟棄：98.6%
    乾淨文件被誤丟：5.3%
    仍有參考資料可回答：94.7%
    觀察：成功的 3 次全部來自同一種攻擊——語氣像正式「管理員通知」、沒有明顯指令標記的內容，
          是目前最難偵測的類型。

(4) 實驗三：消融實驗（每組 132 次）
    配置                    攻擊成功率 (95% CI)   被封鎖   可回答比例
    無防禦                  71% (63~78)           0%       100%
    只開 L1                 42% (34~50)           0%       100%
    只開 L2                  6% ( 3~12)           0%       100%
    只開 L3                 47% (39~55)           0%       100%
    只開 L5                 12% ( 8~19)           60%       40%
    L3 + L5                  7% ( 4~12)           39%       61%
    L3 + L4 + L5             8% ( 5~14)           38%       62%
    L3 + L4(JSON) + L5       0% ( 0~ 3)           0%       100%
    完整 L1~L5               2% ( 1~ 6)           5%        95%
    觀察：
    - 重新訓練後，L2 是效果最好的單一層。
    - L5 能擋下被注入的回答，但擋下後使用者也拿不到答案；
      在文件層先丟掉有毒文件（L1/L2）更能保留可用性。
    - 強制 JSON 格式輸出（L4）效果最好，且不影響正常回答。

(5) 實驗四：誤報率（93 筆未參與訓練的良性問題，完整五層防禦）
    FPR = 2.2%（2/93）
    誤擋的 2 筆都是邊界案例：一筆翻譯請求（被 L2 誤判）、一筆在問句中提到「忽略先前指令」
    （被 L1 黑名單誤判）。
    另外，實際檢索時乾淨文件被丟棄的比例為 10.8%，高於離線評估的 4.5%，
    因為被誤判的幾段（防禦設計、提示詞加固範例）剛好是安全相關問題最常檢索到的內容。

(6) 實驗五：自建繁體中文攻擊資料集
    直接注入 10 筆：無防禦時即為 0%，防禦後全部在 L1/L2 被擋下。
    間接注入 20 個情境：25% → 0%。

(7) 整合評估（212 筆使用者輸入攻擊 + 80 個間接注入情境 + 93 筆良性問題）
                              無防禦      完整防禦
    整體攻擊成功率            12.3%       0.7%
      使用者輸入攻擊           0.5%        0.0%
      間接注入                43.8%        2.5%
    誤報率                     0%          3.2%
    延遲增加                   —          +1152 ms
    觀察：gpt-4o-mini 本身已能抵抗幾乎所有直接注入，主要威脅來自知識庫中的間接注入。

六、已知限制
================================================================================
1. 延遲未達標：增加的 1152 ms 主要來自 L5 的 gpt-4o 稽核；L2 在 GPU 上只約 90 ms。
2. L2 對「換句話說」的攻擊問句偵測能力下降：訓練資料中有大量「討論攻擊手法」的
   安全文件被標為正常，使模型對攻擊語句較保守。目前查詢端仍有 L1、L3、L5 與模型本身的
   安全訓練作為補強。
3. 測試用的間接注入攻擊只有 5 種，且攻擊目標都是「讓模型輸出特定字串」；
   資料外洩、植入連結等其他攻擊目標尚未納入主要實驗。
4. 防禦後的攻擊成功率已接近 0，各配置間的差異需搭配信賴區間解讀。

================================================================================
七、下一步規劃
================================================================================
1. 降低延遲：L5 只在規則檢查判定可疑時才呼叫 gpt-4o 稽核，或改用較小的稽核模型。
2. 降低乾淨文件誤丟：補充「看起來像攻擊、其實是教學內容」的訓練樣本，
   或改為只移除文件中被判定的片段，而非丟棄整份文件。
3. 消融實驗加入「完整五層 + JSON 格式輸出」配置，確認是否為最佳組合。
4. 擴充間接注入攻擊類型（偽裝成正常公告、資料外洩、植入連結等），
   並以「管理員通知」這類漏網案例作為報告中的討論重點。
5. 改善 L2 查詢端的泛化能力（增加多樣化的攻擊問句，或分別訓練查詢與文件用的模型）。
