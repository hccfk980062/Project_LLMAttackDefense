================================================================================
一、研究背景與目標
================================================================================
Prompt Injection 被 OWASP LLM Top 10（2025）列為 LLM 應用的首要風險（LLM01）。
分為兩種：
  ‧ 直接注入：攻擊者在使用者輸入中夾帶惡意指令。
  ‧ 間接注入：攻擊者事先污染 RAG 的知識庫，使用者問正常問題時，惡意指令隨檢索結果進入模型。

研究缺口（計畫書 1.3）：多數防禦只處理直接注入；現有方案多為單點修補。

計畫書四項目標與目前狀態：
  1. 建立 RAG 問答系統原型（文件上傳、向量搜尋、提示詞組合、LLM 生成）   已完成
  2. 設計攻擊資料集（直接、間接、多語言混淆、越獄、Prompt Leaking 五類）   已完成
  3. 實作五層防禦框架                                                     已完成
  4. 以 ASR / FPR / F1 / 延遲量化評估                                       已完成，但是延遲未達標

量化目標（計畫書 4.3）與目前結果：
  指標              目標          目前結果                               狀態
  --------------------------------------------------------------------------------
  攻擊成功率 ASR    < 20%         整合評估 0.7%；間接注入實驗 2.3%       達成
  誤攔截率 FPR      < 5%          2.2% ~ 3.2%                            達成
  偵測器 F1         > 0.90        文件層級 0.936；查詢層級 0.629         部分達成
  延遲增加          < 500 ms      +1152 ms                               未達成


================================================================================
二、系統組成
================================================================================
(1) RAG 問答系統（src/rag/）
    ‧ 知識庫：data/raw/documents/ 共 13 份文件（OWASP、Prompt Injection、RAG 安全、
      防禦技術、AI 安全 FAQ、台灣資安產業報告、雲端運算、台灣旅遊、Python 教學、
      公司資安政策、機器學習、英文客服 FAQ、提示工程），切成 67 個 chunk（512 字 / 重疊 64）。
    ‧ 向量庫：FAISS + OpenAI text-embedding-3-small；檢索 top-k = 5。
    ‧ 生成模型：gpt-4o-mini（temperature 0）。

(2) 五層防禦管線（src/defense/，協調者為 pipeline.py 的 DefensePipeline）
    層級  名稱         作法                                                  主要對付
    ----------------------------------------------------------------------------------------
    L1    輸入清理     Unicode 正規化、去 HTML、長度上限、27 條正則黑名單     已知模式的直接注入
                       （configs/blacklist.txt）；另以結構特徵掃描檢索文件
    L2    注入偵測器   微調 bert-base-multilingual-cased 二元分類器；          直接 + 間接注入
                       掃描使用者查詢，並以 320 字滑動視窗掃描檢索文件
    L3    提示詞分區   [SYSTEM] / [CONTEXT] / [USER] 標籤 + 信任邊界規則        指令覆蓋
    L4    受控生成     temperature 0、輸出長度上限、可選 JSON 固定格式          越獄、輸出操控
                       {answer, sources, refused}、可選 Llama Guard
    L5    輸出驗證     通用正則、格式合規檢查、獨立模型 gpt-4o 稽核             資訊洩漏、有害輸出

    設計重點：
    ‧ L1/L2 掃描檢索文件時，只丟棄被判定的文件，不擋整個問題（使用者的問題本身是正常的）。
    ‧ L2 的用途是「檢查文件中是否夾帶間接注入指令」，有兩個入口：
        - 上傳文件時（POST /documents/upload）先掃描，被標記的段落不寫入知識庫；
        - 查詢時再掃描檢索到的文件，作為第二道防線。
    ‧ 每層都可單獨開關（enabled_layers），供消融實驗使用；參數集中在 configs/default.yaml。

(3) 攻擊模組（src/attack/）
    ‧ 程式產生的使用者輸入攻擊 212 筆：
        越獄 96、直接注入 78、多語言混淆 20、Prompt Leaking 18
    ‧ 間接注入：5 種實驗用 payload（MARKER_PAYLOADS），要求模型輸出特定標記字串
      （如「[已入侵]」「[DEBUG: PWNED]」「確認碼: XK-7749」），以標記是否出現判定成功。
    ‧ 觸發問題：44 個（涵蓋全部 13 份文件；原始 8 個保留為 original 組）。
    ‧ 自建繁中資料集（data/chinese_attack_set/）：直接注入 10 筆（10 個子類別）、
      間接注入文件 5 份。
    ‧ 外部資料集：AdvBench 520 筆、JailbreakBench 100 筆（以越獄類別計分）。
    ‧ PoisoningRetriever：每次檢索時把 payload 注入第 1 份文件，保證毒文件一定進入 context，
      用來單獨量測「防禦能否擋住」。

(4) L2 偵測器訓練（scripts/build_detector_dataset.py → models/detector/train.py）
    ‧ 訓練資料 1,520 筆（良性 760 / 攻擊 760），包含：
        - 查詢層級樣本（模板 + 資料增強）
        - 知識庫文件視窗：乾淨片段（良性）與插入訓練用 payload 的片段（攻擊）
    ‧ 依 group_id 切分 train / val / test（同一句的增強變體、同一份文件的視窗不會跨組），
      避免資料洩漏。
    ‧ 兩組保留評估集（不參與訓練）：
        - ood：38 筆人工手寫的改寫句（24 攻擊 + 14 良性）
        - ood_doc：3 份保留文件（03 RAG 安全、08 台灣旅遊、13 提示工程）的視窗
    ‧ 訓練環境：RTX 3060 Laptop GPU，約 4 分鐘（CPU 約 2 小時）。

(5) 評估框架（src/evaluation/）
    ‧ 指標：ASR、FPR、偵測器 F1、延遲（含與 baseline 的延遲差、純防禦成本）。
    ‧ 所有比率附 Wilson 95% 信賴區間。
    ‧ 另有兩個可用性指標：
        - 乾淨文件誤丟率：被丟掉的文件中，原本沒被污染的比例
        - 可回答比例：沒被擋下、且至少保留 1 份參考資料的問題比例
      用來避免「把參考資料全丟光」被誤認為防禦有效。
    ‧ 良性問題：93 筆從未進入 L2 訓練資料的問題
      （知識庫 44 / 一般 19 / 含敏感字的邊界案例 22 / 多語言 8）。

(6) API（api/，FastAPI）
    POST /rag/query            單一查詢，可切換防禦，回傳各層紀錄與被丟棄的文件
    POST /documents/upload     上傳 .txt/.md/.pdf/.docx，入庫前先以 L1/L2 掃描
    GET  /documents            列出知識庫來源
    POST /experiment/ab        同一問題跑多種防禦配置做 A/B 比較
    POST /evaluation/run       背景執行評估

(7) 測試：pytest 144 項全部通過（不需 API 金鑰）。其中包含資料洩漏防護測試：
    實驗 payload、保留文件、良性問題都不會進入 L2 訓練資料；L5 的預設規則不含實驗的標記字串。


================================================================================
三、實驗設計與結果（2026-10-25）
================================================================================
試驗規模：實驗一～三，每種配置 = 44 個觸發問題 × 3 種知識庫污染方式（毒化 30% 的 chunk）
          = 132 次。括號內為 95% 信賴區間。

(0) 初步實驗：無防禦時的直接注入
    ASR 0%（0/45）。gpt-4o-mini 本身已能抵抗簡單的直接注入。

(1) 實驗一：無防禦時的間接注入
    乾淨知識庫     ASR 0%（0/44）
    被污染知識庫   ASR 72.0%（95/132，64% ~ 79%）
    → 使用者只問正常問題，模型就會執行知識庫中的惡意指令。間接注入是主要威脅。

(2) 實驗二：完整五層防禦 vs 無防禦
    ASR：70.5% → 2.3%（3/132，0.8% ~ 6.5%）
    被污染文件被丟棄 98.6%；乾淨文件被誤丟 5.3%；仍有參考資料可回答 94.7%
    漏網的 3 次都是語氣像正式「管理員通知」、沒有明顯指令標記的 payload。

(3) 實驗三：消融實驗（每種配置 132 次）
    配置                    ASR (95% CI)      被封鎖   可回答
    無防禦                  71% (63 ~ 78)     0%       100%
    只開 L1                 42% (34 ~ 50)     0%       100%
    只開 L2                  6% ( 3 ~ 12)     0%       100%
    只開 L3                 47% (39 ~ 55)     0%       100%
    只開 L5                 12% ( 8 ~ 19)     60%       40%
    L3 + L5                  7% ( 4 ~ 12)     39%       61%
    L3 + L4 + L5             8% ( 5 ~ 14)     38%       62%
    L3 + L4(JSON) + L5       0% ( 0 ~  3)     0%       100%
    完整 L1 ~ L5             2% ( 1 ~  6)     5%        95%
    發現：
    ‧ L2 是效果最好的單一層。
    ‧ L5 能擋下被注入的回答，但被擋下後使用者也拿不到答案；
      在文件層（L1/L2）先丟掉毒文件更能保留可用性。
    ‧ 強制 JSON 格式輸出（L4）效果最好，而且不影響正常回答。

(4) 實驗四：誤攔截率（93 筆良性問題，完整防禦）
    FPR 2.2%（2/93，0.6% ~ 7.5%）
    誤擋 2 筆皆為邊界案例：一筆翻譯請求（L2）、一筆問句中提到「忽略先前指令」（L1）。
    實際檢索時乾淨文件被丟棄 10.8%（高於離線評估的 4.5%，因為被誤判的教學段落
    正好是安全相關問題最常檢索到的內容）。

(5) 實驗五：自建繁中資料集
    直接注入 10 筆：無防禦時即為 0%；防禦後全部在 L1（8）/ L2（2）被擋下。
    間接注入 20 個情境：25% → 0%。

(6) L2 偵測器離線評估（不需 API）
                                  舊模型（9/14）   目前模型
    乾淨文件誤丟                  98.5%            4.5%
    被污染文件偵測                100%（全判）     88% ~ 99%
    ood_doc（保留文件）F1         —                0.936
    ood（手寫改寫攻擊句）F1       0.83             0.629
    掃描延遲（top-5，GPU）        —                約 91 ms

(7) 整合評估（212 使用者輸入攻擊 + 80 間接注入情境 + 93 良性問題）
                           無防禦      完整防禦
    整體 ASR               12.3%       0.7%
      使用者輸入攻擊        0.5%        0.0%
      間接注入             43.8%        2.5%
    FPR                     0%          3.2%
    良性問題平均延遲      1618 ms     2769 ms（+1152 ms）

主要結論：
  1. 對現代模型（gpt-4o-mini）而言，直接注入幾乎無效；間接注入才是 RAG 系統的主要威脅
     （無防禦時 ASR 44% ~ 72%）。
  2. 五層防禦可將間接注入 ASR 降到 2% ~ 3%，同時 FPR < 5%、95% 的問題仍能正常回答。
  3. 最有效的手段是「在文件層丟掉毒文件（L2）」與「強制結構化輸出（L4 JSON）」；
     在輸出端封鎖（L5）雖然有效，但會犧牲可用性。


================================================================================
四、已知限制
================================================================================
1. 延遲未達標（+1152 ms）：主要來自 L5 的 gpt-4o 稽核；L2 在 GPU 上只約 90 ms。
2. L2 對手寫改寫的攻擊問句偵測能力較弱（ood F1 0.629）。原因是訓練資料中大量
   「討論攻擊手法」的安全文件被標為正常，模型對攻擊語句變得保守。
3. 乾淨文件在實際檢索中仍有 10.8% 被誤丟，集中在示範攻擊／防禦寫法的教學段落。
4. 間接注入的實驗 payload 只有 5 種，且目標都是「輸出特定字串」；資料外洩、植入連結等
   攻擊目標尚未納入主要實驗。
5. 整合評估報告中的偵測器 F1（0.993）使用與訓練資料同模板的樣本，屬於 in-distribution，
   論文中應引用 ood / ood_doc 的數字。
6. 防禦後 ASR 已接近 0，配置之間的差異需搭配信賴區間解讀。


================================================================================
五、下一步
================================================================================
1. 降低延遲：L5 只在規則檢查判定可疑時才呼叫 gpt-4o，或改用較小的稽核模型。
2. 降低乾淨文件誤丟：補充「像攻擊、其實是教學內容」的訓練樣本；
   或改為只移除文件中被判定的片段，而非丟棄整份文件。
3. 消融實驗加入「完整五層 + JSON 輸出」配置。
4. 擴充間接注入攻擊類型（偽裝正式公告、資料外洩、植入連結），
   並以「管理員通知」漏網案例作為報告討論重點。
5. 改善 L2 查詢端泛化（更多樣的攻擊問句，或查詢與文件分別訓練模型）。
6. 計畫書延伸方向：多智能體系統的注入傳播、對抗訓練、差分隱私防止知識庫污染。

  3     python scripts/train_detector.py --no-wandb               否

  6     python scripts/Experience_2/run_indirect_defense.py       是
